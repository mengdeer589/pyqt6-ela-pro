## #2 ElaMenu：checkable 项使 addElaIconAction 图标不渲染 —— ✅ 成立

**代码证据**（`PyElaWidgetTools/ElaWidgetTools/ElaWidgetTools/Development/ElaMenuStyle.cpp`）：

- `:93` `if (mopt->menuHasCheckableItems)` → 图标列只画 Check / None 字形（`:101`），且整个分支**从不读** `menuIcon` / `ElaIconType` 属性；
- `:104-133` else 分支才读 `action->property("ElaIconType")` 画 ElaAwesome 字形（`:113`）、或退到 `QIcon`（`:129-131`）。

**运行时探针**（直接驱动 C++ `ElaMenuStyle.drawControl(CE_MenuItem)`，同一 action、同一几何，仅 `menuHasCheckableItems` 变化）：

| 场景 | 图标列墨色像素 |
| --- | --- |
| checkable 标志 + 未勾选 | **0px**（图标消失） |
| checkable 标志 + 已勾选 | 38px（勾字符，非图标） |
| 无 checkable 标志 | **111px**（图标正常绘制） |

**旁证**：本仓库 `AGENTS.md:399` 已把它写成硬约束（「菜单里不许出现 checkable 项……图标列与勾选框互斥」），托盘宿主按「文案 + 换图标」规避 —— 与报告「项目侧是否有规避」段落完全吻合。

## #10-A ElaContentDialog / ElaMessageDialog 高度不重适配 —— ✅ 成立

**代码证据**：

- C++ `ElaContentDialog.cpp:30` 构造器 `resize(400, height())`（此刻 `height()` 还是默认 30 → 定死 400×30）；
- `:132-141` `setCentralWidget` 只换布局内控件，不重算窗口尺寸；
- `:167-176` `showEvent` 只处理遮罩/居中，**无 `adjustSize()`**；
- Python 侧 `dialog_base.py::_initParamArea` → `super().setCentralWidget(...)`、`message_dialog.py::setMessage` 追加 `ElaText`，全链也没有尺寸自适应。

**运行时探针**（offscreen，长文案取自报告原文）：

- 构造后 400×30 → `show()` 后 400×132（`sizeHint` 525×145，窗口连宽度也小于内容期望）；
- message label：几何 `(25,42,350x15)`，`heightForWidth(350)=26` → **15 < 26，正文被垂直裁切**；
- 短文案对照：label 高 13 = `heightForWidth(350)` 13，**不裁切** —— 与报告的「一行短文本开箱无感」一致。

数值（400×132 / sizeHint 145 / label 15 / 需 25~26）与报告逐项吻合。

## #10-B 非主屏最大化 isFullScreen() 误报 → 标题栏失效 —— ⚠️ 本机未复现（触发条件不满足）

**代码证据**（`ElaAppBar.cpp`）：`:644` `if (d->_containsCursorToItem(this) && !window()->isFullScreen())` → `HTCAPTION`；否则落到 `:649` `HTCLIENT`。**只要 `isFullScreen()` 误报为真，整条标题栏命中确实会失效** —— 报告描述与代码一致。
（另注：`_containsCursorToItem` 判的是 `QCursor::pos()`（`ElaAppBarPrivate.cpp:232`），不是消息坐标。）

**运行时探针**（本机 Win10/Qt 6.8.4，双屏）：

- 副屏最大化后：裸无边 QWidget `isFullScreen()=False`、ElaWindow `isFullScreen()=False` —— **无误报**；
- 把真实光标移到标题栏后发 `WM_NCHITTEST`：副屏普通 / 副屏最大化 / 主屏最大化（对照）均返回 **HTCAPTION**（可拖动），无报告中的「整条 HTCLIENT」。

**未复现原因**：本机两块屏**都带任务栏**（`availableGeometry` ≠ `geometry`），报告触发条件是「无任务栏副屏 + 无边窗恰好铺满 → Qt 5.15 平台插件误判 fullscreen」，属 Win7 + Qt 5.15 环境；Win10/Qt 6.8.4 不满足该条件。

## #12 终端全幅重绘 ~83ms —— ⚠️ 机制属实、性能未复现

**代码证据**（`terminal_view.py`）：`:142` `_DEFAULT_FONT_FAMILY = "Consolas"`；`_render_line`（`:1868`）对每个 span 都 `insertText(text, fmt)`，`_format_for`（`:1893`）**连默认色也显式写 foreground/background** —— 报告所说「逐行 char format（含与默认色相同的 plain 行）」属实。

**运行时探针**（在屏窗口，1500 行 CJK 日志 618×455，`viewport().repaint()` 中位数）：

| 对象 | 本机实测 | 报告 |
| --- | --- | --- |
| ElaTerminalView（Consolas + 逐行格式） | **2.6 ms** | 82.7 ms |
| 裸 QPlainTextEdit（对照） | **5.5 ms** | 3.8~5.5 ms |

对照组数字与报告一致 → 口径可比；ElaTerminalView 在**本机反而比裸编辑框更快**，83ms 量级不复现。报告将其归因于 Win7 DirectWrite shaping 无跨 paint 缓存——属环境行为。

## #13 setResizeReflowDeferred 冻结失效 —— ✅ 成立

**代码证据**（`chat/view.py`）：`:1872-1875` `resizeEvent` 先 `super().resizeEvent(event)`、再 `_on_view_resized(event.size().width())`；`:1920-1924` 冻结值取 `self._content.width()` —— 此时布局 pass 已把内容拉到新视口宽，冻结值=新宽。

**运行时探针**（offscreen，40 条消息，`minMessages=10`）：

- 初始：view=680 / viewport=670 / content=670；
- `resize(780)` 后：viewport=770、content=770、**`_resize_frozen_width=770`** → 冻结值=新内容宽 → 无 letterbox、逐帧重排照发生。

与报告（冻结值 = 新内容宽 = 不省重排）完全一致。

## #16 combo_box.py 顶层 import pypinyin —— ✅ 成立
