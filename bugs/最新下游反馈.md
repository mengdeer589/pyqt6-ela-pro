#22 PyQt6 绑定层：无参 pyqtSignal() 连 list.append（绑定内建方法）→ emit() 确定性原生崩溃，进程静默 exit 21 

库/组件：PyQt6 6.8.1 绑定层信号发射路径（无参信号 + 绑定内建方法 receiver 的组合；镜像 Win7 构建）。 

- 现象（2026-10-23 实测，定位自 ElaSpotlight.finished（无参信号）测试接线）：无参 pyqtSignal() 连上 list.append 后 emit()，进程确定性原生崩溃——无 Python 回溯（faulthandler / sys.excepthook 均不触发，纯 C 层终止），退出码 21。三组对照钉死边界： 

1. 崩：纯 QObject + pyqtSignal() + sig.connect(out.append) + sig.emit() → exit 21（零 ela 组件、零 widget，与库组件无关）； 

2. 过：同一无参信号 + sig.connect(lambda: out.append(1)) → 正常； 

3. 过：pyqtSignal(int) + sig.connect(out.append) + emit(5) → 正常 ([5])。
即「无参信号 × 绑定内建方法 receiver」双条件同时满足才崩——单独无参信号或单独连 list.append 都不崩。 

复现（一行脚本，任何PyQt6进程可复现）： 

```python
from PyQt6.QtCore import QObject, pyqtSignal
class 0(QObject):
    sig = pyqtSignal()
o = 0()
out = []
o.sig.connect(out.append)
o.sig.emit() # → 进程静默 exit 21 
```

- 期望行为：无参信号调用一参槽（如 list.append）至多按 Python 语义抛 TypeError（参数个数不符），不应在绑定层触发原生 AV；至少崩溃前留可诊断的异常路径。 

- 项目侧临时规避及移除条件：无生产代码影响（已 grep 全 app/，无「无参信号 + 内建方法 .append 直连」模式；ElaSpotlight.finished 等无参信号宿主侧一律 lambda 接收）。测试/探针约定（已写入 AGENTS.md 易错约定）：无参 pyqtSignal() 的 receiver 不得直传绑定内建方法（list.append 等），一律 lambda / 自定义槽。绑定层修复发布后移除本条与约定。
