## 发现清单

### F6（高）`_motion.py:86` 系统动效探测用了错误且危险 SPI 常量

- **位置**：`_motion.py:85-86`（`_SPI_GETCLIENTAREAANIMATION = 0x0049`）、`_motion.py:184-186`（调用点）。
- **事实**：`SPI_GETCLIENTAREAANIMATION` 的值是 **`0x1042`**；**`0x0049` 是 `SPI_SETANIMATION`（写操作）**，它期望 `uiParam==sizeof(ANIMATIONINFO)==8`、`pvParam` 指向 `ANIMATIONINFO`，而调用点传的是 `uiParam=0` + `byref(c_int(0))`。
- **后果**：
  1. 探测实际返回 FALSE（参数校验失败）→ `_probe_system_reduced()` 恒为 `False` → **「跟随系统关闭动画」这一无障碍默认永不生效**（Windows 里关掉动画的用户仍会看到全部动效）；
  2. 更糟的一面：这是一个**用 SET 常量当 GET 调用**的写操作（`fWinIni=0` 只影响会话、不落盘，但参数一旦恰好满足校验就会改写用户动画设置）——与 AGENTS.md 记录的「0x004B 误当读取项调用」是同一类错误。
- **为什么没被测出来**：`tests/motion/test_motion_policy.py` 只 monkeypatch `_probe_system_reduced`，**真实探测函数无任何测试覆盖**（仓库内也没有正确常量可对照）。
- **修复建议**：常量改为 `0x1042`；补一条廉价守卫测试断言常量值（`assert _SPI_GETCLIENTAREAANIMATION == 0x1042`）；有条件时在真机验证「关系统动画 → motion.mode() == Reduced」。修复前**不要**运行真实探测（写操作风险）。

### F4（中）`ela_side_drawer.py:304-331` 异常分支留下「关不掉的抽屉」

- **位置**：`showDrawer()` 的 `try/except`。
- **现象**：`try` 内已执行 `_drawer_widget.show()` / `_dim_widget.show()` / `self.show()`（312-316 行），随后任一步（如 `start_transition`）抛异常 → `except` 只 `print(e); return`，而 `_is_opened` 保持 `False`。
- **后果**：遮罩 + 抽屉面板已显示，但 `closeDrawer()` 首行守卫 `if not self._is_opened or self._is_closing: return` 直接返回 → **面板关不掉、无报错**；`isOpened()` 还报 False，宿主状态与视觉相反。
- **修复建议**：`except` 内回滚（`_drawer_widget.hide()` / `_dim_widget.hide()` / `self.hide()` + 还原 eventFilter）或补完状态转换；顺带把 `print` 改为库约定告警。

### F8（低）`splash_screen.py` 的两个「一次性语义」边界

- **`finish()` 的 timeout 连接不在 `__init__` 里**（`splash_screen.py:252`）：`close()` 之后再调 `finish()` 会**重复 connect** `_onFadeTick` → 每次 tick 跑两遍、收尾 `_settleFadeOut` 跑两遍（`closed` 信号重复发射、主窗口被 show/raise 两次）。建议把连接移到 `__init__`（或 connect 前先 disconnect）。
- **`_fade_settled` 在 `show()` 不复位**（`splash_screen.py:96/247/266`）：复用同一个 splash（`finish()` → 再次 `show()` → `finish()`）时第二次 `finish()` 被 `if ... or self._fade_settled: return` 静默吞掉 —— 启动画面不淡出、主窗口永不显示。一次性组件常见，但复用路径没有任何告警。建议 `show()` 里复位 `_fade_settled` / `_fade_opacity` / `_fade_target`。
- 备注：`show()` 只在主屏居中（`QApplication.primaryScreen()`），多屏时忽略 app 实际所在屏。低优先。

### F11（低）`__init__.py:9-35` 仍带 Win7 DirectWrite 补丁（与 AGENTS.md「已删」矛盾）

- **事实**：`pyqt6_ela_pro/__init__.py` 在 import 期检测 Win7（`major==6 and minor==1`）并 `qInstallMessageHandler` 装一个全局消息过滤器（过滤 `CreateFontFaceFromHDC() failed`）；**HEAD 里就有**（非在途改动）。而 AGENTS.md 明确写「**`__init__.py` 不再有 Win7 DirectWrite 补丁（Qt 6.8 起不支持 Win7，补丁随迁移删除）**」——文档与代码不一致。
- **影响**：支持的系统（Win10/11）上是死代码；只有 Win7（Qt 6.8 本就不支持）会真的改宿主全局 Qt 消息处理器（import 期副作用）。链路本身写得对（`qInstallMessageHandler(None)` 先摘旧、过滤器再转发），不构成缺陷，但属于「文档说没有、代码里还在」的漂移。
- **建议**：按 AGENTS.md 删除，或反过来更新 AGENTS.md 并说明保留理由；二选一，别两边各说各话。

### F12（高）图标参数未归一：`ElaButton` / `ElaProgressButton` 传 int 图标 = **首帧 paint 崩进程**

- **实测（子进程逐组件探针，`setElaIcon(3)` → show → processEvents）**：

  | 组件 | 结果 |
  |---|---|
  | `ElaButton`（`setElaIcon` / 构造 `icon=`） | **exit 3221226505（0xC0000409）、零 traceback** |

### F13（中高）`ElaDropDownButton` / `ElaSplitButton`：菜单被删后点击 = **崩进程**
