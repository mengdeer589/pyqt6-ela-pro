## #2 ElaMenu：checkable 项使 addElaIconAction 图标不渲染

**层面**：`PyElaWidgetTools/ElaWidgetTools/`（C++ 子模块）→ 需重建绑定轮子。

**根因**（已核实）：`Development/ElaMenuStyle.cpp:93` 的 `if (mopt->menuHasCheckableItems)` 分支只画 Check/None 字形且**从不画项图标**；else 分支才读 `action->property("ElaIconType")`。

**方案**：勾选列与图标列分列（左起：勾选列 → 图标列 → 文本），两处代码同步：

1. `ElaMenuStyle::drawControl`（`CE_MenuItem` 非分隔符分支，`:76-147`）：
   - 取 `const qreal checkColumnWidth = mopt->menuHasCheckableItems ? _iconWidth * 0.8 : 0.0;`
   - checkable 分支：勾选字形仍在 `menuRect.x() + contentPadding` 画（位置不变）；
   - 图标绘制（原 else 分支逻辑）：x 起点改为 `menuRect.x() + contentPadding + checkColumnWidth`；
   - 文本 x（`:142`）：在原式上追加 `+ checkColumnWidth`（即 `... + _iconWidth + checkColumnWidth`）。
2. `ElaMenuStyle::sizeFromContents`（`CT_MenuItem`，`:201-227`）：
   - `mopt->menuHasCheckableItems` 时宽度 `+= qRound(checkColumnWidth)`（否则两列会挤掉文本；有子菜单的 `+20` 逻辑保持不变）。

**验收**：复跑第三方探针 `probes/recheck_menu_checkable_iqon.py`（或等价脚本），断言「checkable 项图标列墨色 > 0」；本机已备同款探针（`p_menu.py`，三档墨色 0/38/111px 可做对照）。

**同步项**：
- 重建 `PyElaWidgetTools` 轮子并按 AGENTS「Hash mismatch」流程更新 `uv.lock`；
- 更新 `AGENTS.md` 两处「图标列与勾选框互斥」约束（line 141 右键菜单条 ②、line 399 托盘条）→ 改为「分列共存（修复后）」；
- 宿主可选恢复托盘/模式菜单图标（宿主侧事项）。

**风险**：菜单项宽度会变宽（多一列）；用现有 3 处 ElaMenu 场景目测 + 探针回归即可。

## #10-A ElaMessageDialog / ElaContentDialog：多行正文被裁切

**层面**：Python 库 `dialog_base.py`（上游 C++ 可另做，非必须）。

**根因**（已核实）：C++ 构造器 `resize(400, height())` 定死 400 宽；`setCentralWidget` / `showEvent` 都不按内容自适应 → 长文案 label 只分到 15px（需要 26px）。

**方案**（探针验证过的实现）：在 `ElaDialogBase` 增加「内容自适应」，`showEvent` 里执行：

```python
_AUTO_FIT_MAX_WIDTH = 620

def setAutoFit(self, on: bool = True) -> None:   # 宿主需要固定尺寸时关闭
    self._auto_fit = bool(on)

def _fit_to_content(self) -> None:
    layout = self.layout()
    layout.activate()
    hint = self.sizeHint()
    width = max(self.minimumWidth(), min(hint.width(), _AUTO_FIT_MAX_WIDTH))
    self.resize(width, self.height())      # 先定宽，让换行按目标宽度算
    layout.activate()
    height = max(self.minimumSizeHint().height(), layout.heightForWidth(width))
    self.resize(width, height)
    layout.activate()

def showEvent(self, event) -> None:
    if self._auto_fit:
        self._fit_to_content()
    super().showEvent(event)               # 之后 C++ 的 _moveToCenter 会用新尺寸居中
```

**验证数据**（本机探针）：短文案 560×145（label 26 = 需要 26，OK）；长文案（~276 字）620×210（label 91 = 需要 91，OK）；未修时两档均裁切（15 < 26 / 52 < 104）。
说明：`adjustSize()` 单用不够——顶层窗口会被 Qt 钳到 2/3 屏宽、且高度不走 `heightForWidth`（探针实测 533×171 仍裁切），所以必须用「定宽 → 布局 hfw 求高」。

**可选**：宿主设置过 `minimumWidth`（既有 5 处 `560`）仍然生效；修复后宿主可删除 `setMinimumWidth(560)+adjustSize()` 组合。上游 C++ 侧（非 Python 用户）可在 `ElaContentDialog::showEvent` 做同样逻辑，作为独立条目排期。

**测试**：`tests/dialog_base/`（或 message_dialog 用例）：长/短文案 show 后 `label.height() >= label.heightForWidth(width)`；`setAutoFit(False)` 保持旧行为。

**同步项**：`AGENTS.md`「对话框基座（`dialog_base.py`）」节补条目；`example/drawer_tooltip_page.py` 的消息对话框 demo 无需改（自动受益）。

## #12 终端全幅重绘 ~83ms（Win7）

**层面**：Python 库 `terminal_view.py` + **环境限制**（Win7 DirectWrite shaping；本机不复现）。

**根因**（报告归因，已核实代码事实）：Consolas 纯 Latin + CJK 逐字 fallback、逐行 char format 放大片段/shaping 单位；C++ ElaPlainTextEdit 无跨 paint 的 shaping 缓存。

**方案**（对应报告期望的三条，前两条可做）：

1. **新增字体族 API（低风险，建议先做）**——`ElaTerminalView.setFontFamilies(families: list[str])`：
   - 内部走 Qt6 `QFont.setFamilies()`（`_apply_font` 处组装 `QFont`）；
   - 默认保持 `["Consolas"]` 不变；文档写明 **CJK 密集场景**可传 `["Consolas", "Microsoft YaHei UI"]` 等（避开逐字形 fallback，Win7 上按报告有量级收益，需实测）。
2. **（可选）`_render_line` 相邻同样式 span 合并**：插入前把同一行内 `_format_for(style)` 为同一缓存对象的相邻 span 合并成一次 `insertText`，减少片段边界；过滤高亮路径不变（注意：合并后跨 span 边界的过滤命中会变成可命中——属改进，测试里钉住）。
   > 报告期望的「与默认色相同的 span 不写 char format」**不能照字面做**：C++ `ElaPlainTextEdit::paintEvent`（`ElaPlainTextEdit.cpp:146`）会把 palette `Text` 强制刷回主题 `BasicText`，而终端调色板的默认前景是独立定义的（如 one-dark 浅色 `#383a42`，见 `_TERMINAL_THEMES`）——省略格式会直接换色。故采用「合并写入」这条等价降本路线。
3. **不做、记录**：C++ paint 级 shaping 缓存 = Qt `QPlainTextEdit` 文本布局 + Win7 DirectWrite 行为，绑定层无干预点 —— 作为「Win7 已知环境限制」写入 `docs/`（附报告探针结论与复现脚本），或向 Qt 反馈。

**验收**：在 Win7 上用第三方探针 `probes/recheck_terminal_repaint.py` 做 A/B（现状 vs 选项 1 vs 选项 1+2）；本机（对照组可比）可验「无非目标劣化」。

**测试**：`tests/ela_terminal/` 增：`setFontFamilies` 生效（`edit.font().families()`）；合并逻辑的样式等价（有 ANSI 色的行仍逐段正确；纯文本行 1 次写入）。

**同步项**：AGENTS「内容渲染 → terminal」节；示例 `example/` 终端页可加一个字体族切换 demo（可选）。

## #13 setResizeReflowDeferred 冻结失效

**层面**：Python 库 `chat/view.py`。**本机已复现、改法已验证。**

**根因**（已核实）：`resizeEvent` 在 `super()` 之后才取 `self._content.width()` 作冻结值，而此刻布局已把内容拉到新宽（`frozen=770=新宽`）。**注意：`super()` 之前读 viewport/内容宽也无效——那时它们同样已经是新宽（探针实测 pre=post=770）；`event.oldSize()` 才能拿到旧控件宽（680）。**

**方案**（探针验证：frozen 670 / 770 精确命中）：

```python
def resizeEvent(self, event) -> None:
    self._resize_old_width = event.oldSize().width()   # 新增字段，__init__ 里置 0
    super().resizeEvent(event)
    self._position_jump_button()
    self._on_view_resized(event.size().width())

def _on_view_resized(self, width: int) -> None:
    ...
    if not self._resize_reflow_timer.isActive():
        old_width = self._resize_old_width
        chrome = self.width() - self._scroll.viewport().width()   # 滚动条占位（ElaScrollBar 10px）
        frozen = (old_width - max(0, chrome)) if old_width > 0 else self._content.width()
        if frozen > 0:
            self._resize_frozen_width = frozen
            self._content.setFixedWidth(frozen)
    ...
```

**测试**：`tests/ela_chat/test_chat_perf.py::test_resize_reflow_deferred_freezes_width` 加断言「`_resize_frozen_width` == resize 前的 `_content.width()`」；`test_chat_view.py` 同族用例同步（目前只断言 `> 0`）。

**同步项**：AGENTS「chat 组件 → 大消息量三条」条目补「冻结值取自 `event.oldSize()`」。

## #14 透明 Base 视口（Win7 上 ×8）

**层面**：Python 库 `_styles.py` + `ela_markdown_viewer.py`（可选 `chat/bubble.py`）。本机无性能差（0.91x），方案前提是**保持视觉完全等价**、把「透明视口」换成「同色不透明视口」以绕开 Win7 慢路径；收益需 Win7 实测。

**根因**（已核实）：`setTransparentTextBase` = `Base` 透明 + `viewport.setAutoFillBackground(False)`，构造/换主题即生效；Win7 上透明背景走慢速 paint 路径（报告 P1 118ms vs P2 14.4ms）。

**方案**：

1. `_styles.py`：把原语升级为 `setTextBaseColor(widget, color=None)`（含改名，本库不留旧名）：
   - `None` → 现状（透明 Base + 关自动填充）；
   - `QColor` → `Base = color` + `setAutoFillBackground(True)`（**不透明快路径**）。
2. `ela_markdown_viewer.py`：
   - 新增 `setViewportBackground(color: QColor | None)`（公开 API，camelCase）；
   - `_applyThemeStyle` 里（`:4760`）改为 `_apply_viewport_base()`：
     - 宿主显式设色 → 用宿主色；
     - **非嵌入 viewer**（默认，自己 `paintEvent` 画 `BasicPress` 背景）→ 用 `eTheme.getThemeColor(mode, BasicPress)` 作不透明底（与它自己画的底色**逐像素等价**，无视觉变化）；
     - **嵌入 viewer**（chat 气泡内）→ 默认保持透明（现状）；宿主可传色。
3. （可选二期，需 Win7 确认收益）`chat/bubble.py`：气泡知道自己的 `_bg`，在创建/换肤时把气泡底色传给内部 viewer（`viewer.setViewportBackground(self._body._bg)`），让聊天正文也吃上快路径。

**验收**：非嵌入 viewer 前后 **grab 截图逐像素对比**（离屏可测底色像素，文字像素按仓库既有 `skip_if_no_pixels` 规则跳过）；Win7 上用报告探针 `probes/md_scroll_perf14.py` 复测 P1/P2 差距。

**测试**：`tests/styles/test_styles_primitives.py`（原语：透明档/不透明档的 palette `Base` 与 `autoFillBackground` 状态）+ `tests/ela_markdown_viewer/`（非嵌入默认不透明且等于 `BasicPress`；嵌入默认透明；`setViewportBackground` 生效并随主题重算）。

**同步项**：AGENTS line 126（原语清单 `setTransparentTextBase` 改名）、markdown 渲染节；`docs/markdown.md`。

## #16 combo_box 顶层 import pypinyin（~50 MiB 常驻）

**层面**：Python 库（`_internal.py` + `combo_box.py` + `table_view.py`）。注意：**`table_view.py` 也是模块级导入**（第 37 行 try/except 只是防缺失，仍是 eager），只改 combo_box 不能达成「import 包不背字典」。

**方案**：共用惰性加载器（`_internal.py`）：

```python
_lazy_pinyin_impl = None
_lazy_pinyin_probed = False

def pypinyin_lazy():
    """返回 pypinyin.lazy_pinyin；首次调用才导入（~50 MiB 字典）；缺失返回 None。"""
    global _lazy_pinyin_impl, _lazy_pinyin_probed
    if not _lazy_pinyin_probed:
        _lazy_pinyin_probed = True
        try:
            from pypinyin import lazy_pinyin as impl
        except ImportError:                      # 防御（声明依赖，通常不会走到）
            impl = None
        _lazy_pinyin_impl = impl
    return _lazy_pinyin_impl
```

- `combo_box.py`：删顶层 import；`_pinyin_index` 改为 `impl = pypinyin_lazy()`；`impl is None` → 返回空索引（搜索退化为原文匹配）。
- `table_view.py`：删顶层 try/except；`_sort_by_pinyin` 首个调用处取 `impl`；`None` → 退回 `self._model.sort(...)`（与现状一致）。

**验收**：干净子进程 `import pyqt6_ela_pro` 后 `'pypinyin' not in sys.modules`；后续首次拼音搜索/排序仍正确且此时才加载（`sys.modules` 出现 pypinyin）。

**测试**：`tests/regression/` 新用例（子进程隔离，规避同进程已加载）；既有搜索/表格拼音用例保持绿。

**同步项**：AGENTS「Import 约定」延迟导入清单加入 `pypinyin`（注明 ~50 MiB 字典、声明依赖但惰性）；如 `docs/`/README 有提及同步。
